# Training classifier canvas Aksantara melalui Kaggle MCP

## Context
User meminta mencoba kombinasi arsitektur, transfer learning/fine tuning, hingga ensemble untuk mendapatkan hasil AI terbaik. Cakupan dikonfirmasi: classifier citra karakter canvas Lontara, Sunda, Bali, dengan satu label space dan model deployment terpisah per aksara, memakai kuota Kaggle gratis saja. Hasil akhir adalah eksperimen yang dapat direproduksi, perbandingan kualitas/latensi, dan tiga paket ONNX yang benar-benar diverifikasi; ensemble bukan otomatis pemenang. OCR manuskrip tidak dilatih dalam pekerjaan ini.

### Override eksekusi 13 Oktober 2026
User menginstruksikan melanjutkan training Sunda dan Bali tanpa menjadikan izin lisensi dataset sebagai blocker. `ai/configs/provenance.json` mencatat `training=allowed` sebagai keputusan operasional user, **bukan bukti pemberian hak dari pemilik dataset**; license literal dan `release=unresolved` tetap dipertahankan. Instruksi lama yang menghentikan training Sunda/Bali karena izin pada Approach1.4–1.5, Verification4, dan Assumptions tidak berlaku untuk eksperimen privat ini. Gate integritas data/split, consent tulisan manusia, mapping Unicode, kualitas dan latensi tidak berubah.

## Approach

### 1. Menetapkan gate data dan penggunaan sebelum GPU
1. Buat modul baru `ai/data.py`, CLI `ai/runner.py`, dan konfigurasi `ai/configs/training.json`; tidak ada equivalent lokal. CLI dijalankan dari root repo. Semua generated manifests, checkpoints, PNG canvas, dan reports masuk `ai/runs/` atau `ai/artifacts/` yang di-ignore, bukan Git. Konfigurasi, kode, dan reviewed label/provenance metadata kecil masuk `ai/configs/`.
   CLI defaults: config `ai/configs/training.json`, labels/provenance in `ai/configs/`, audit `ai/runs/audit`, splits `ai/runs/splits`, source root `datasets/canvas_classifier`; `--config`, `--audit`, `--splits`, `--data-root`, `--resume` override these explicitly. Missing required manifest/hash mismatch exits nonzero with exact path/reason; no automatic split regeneration inside train. `--epochs 2 --smoke` overrides total epoch ceiling to two for the smoke only and never marks a full queue item complete.
2. Jalankan `audit` pada empat root kelas persis di tabel. Decode berdasarkan header, bukan ekstensi; apply EXIF orientation, alpha composite, lalu catat `sample_id` (SHA256 script + relative path), path POSIX, script, exact leaf label/category, ukuran bytes, format aktual, width/height/mode, status decode, byte SHA256, decoded-pixel SHA256, dan provenance group. Reconcile inventory terhadap baseline di atas. Corrupt/non-image masuk laporan quarantine tanpa menghapus file sumber; tidak dimasukkan ke training. Empty dataset atau kelas tanpa citra valid: exit nonzero dengan daftar kelas, bukan melatih head yang lebih kecil diam-diam.
3. Buat `ai/configs/labels.json` dengan array per script berisi `class_id` contiguous mulai 0, `source_label` persis, `category`, `display_name`, `unicode_sequence` nullable, `mapping_status` (`unverified`/`verified`), dan `mapping_source`. IDs awal mengikuti urutan lexicographic full relative leaf path, kemudian dibekukan. Ini indexing, **bukan** inferensi Unicode. Pertahankan seluruh 114/30/30 labels termasuk `Ke`/`Ke_`, `ae`/`e`. Ambiguitas mapping boleh menghasilkan benchmark dengan source_label, tetapi tidak boleh menjadi target latihan anak atau release glyph mapping sebelum kurator aksara memverifikasi.
4. Buat `ai/configs/provenance.json`: source URL/version, license literal dan bukti teks, status penggunaan training serta release (`allowed`/`unresolved`/`denied`), attribution, dan hubungan sumber campuran. Periksa metadata MCP dan file/source publisher, termasuk sumber GitHub Sunda. Tidak ada izin eksplisit untuk Sunda/Bali saat ini: jangan mulai GPU pada keduanya sebelum izin noncommercial training tersedia. Untuk Lontara, NC/ND tidak boleh ditafsirkan sebagai izin deployment komersial atau distribusi derivatif/model; tandai release unresolved sampai tim memperoleh keputusan hak yang terdokumentasi. Pipeline memblokir training jika status training bukan allowed, dan memblokir publikasi jika release bukan allowed. Tidak mengganti lisensi dengan klaim buatan.
5. Jika izin tidak diperoleh, gunakan citra tulisan sendiri dengan consent untuk training dan holdout, tetap mencakup label space aksara yang sama setelah kurasi. Data ini boleh diupload sebagai dataset Kaggle **private** bila consent mengizinkan. Jangan reupload dataset publik campuran dengan lisensi tidak jelas. Jika data pengganti belum tersedia, selesaikan kode/audit/harness dan laporkan training aksara terkait blocked dengan prerequisite spesifik; jangan mengaku tiga model selesai.

### 2. Mengunci split bebas kebocoran dan mengukur domain canvas
1. Di `data.py`, identifikasi byte/pixel duplicates sebelum split. Duplikat label sama: simpan satu representative deterministik (relative path terkecil), ancestry tetap tercatat. Duplicate identik lintas label: quarantine semua anggota dan minta kurator menyelesaikan konflik; jangan majority vote. Cari kandidat near duplicates memakai pHash 64-bit setelah canonical polarity, Hamming <=4. Near duplicates belum direview tidak dihapus, tetapi union sebagai konservatif leakage group; audit melaporkan kemungkinan false grouping.
2. `group_id` adalah connected component dari verified writer/page/origin ancestry, exact/near duplicate relation, dan derivative filename stem pada sumber yang sama. Normalisasi suffix `(n)`/` - Copy...` untuk grouping saja, bukan rename. Nama file bukan bukti writer. Recover writer/source metadata dari sumber jika tersedia; jika tidak, metadata `writer_id=null`, benchmark disebut **duplicate/ancestry-group-held-out**, bukan writer-independent. Date/cohort dan kualitas 32×32 Bali dilaporkan sebagai slices, tidak dianggap writer ID.
3. Buat split immutable train/selection/calibration/test dengan target 70/10/5/15 persen per kelas, seed 42; assign group utuh dengan deterministic greedy class-count balancing, prioritaskan coverage semua kelas. Manifest memuat sample_id, class_id, group_id, partition, dataset hash dan label hash. Training/early stopping/ensemble selection tidak membaca test; calibration hanya untuk temperature/threshold. Split tidak berubah antar arsitektur/seeds. Jika independence/coverage tidak feasible, keluarkan daftar kelas dan kebutuhan kelompok tambahan; jangan fallback random file-level split atau menghapus kelas.
4. Buat `ai/harness/index.html` dan `ai/harness/canvas.js` sebagai alat eksperimen lokal: canvas PointerEvents mouse/touch/stylus, stroke width 6 CSS px, DPR-aware, clear/undo, script + source_label selection, pseudonymous writer/device ID, export raw 512×512 PNG dan JSON metadata dengan consent. Tidak merekam identitas pribadi atau memakai glyph/font rendering sebagai test handwriting. Tidak ada model skor saat mengumpulkan test agar label tidak dipilih mengikuti prediksi.
5. Target koleksi minimum per aksara: 10 writer independen, masing-masing 2 tulisan per kelas; 4 writer untuk tambahan train, 2 selection, 2 calibration, 2 test. Writer ID disjoint dan session/device tercatat; pastikan masing-masing val/test mengandung mouse/touch/stylus jika perangkat tersedia, laporkan mode yang benar-benar dikoleksi. Data pada `datasets/canvas_capture/`, import dengan `audit --canvas-root`; ikut leakage checks sumber utama. Data training canvas hanya dari writer train. Jangan menyisipkan canvas selection/calibration/test ke distillation atau augmentasi.
6. Jika koleksi belum lengkap, lakukan eksperimen source-data yang feasible dan laporkan **provisional dataset-only**; tidak klaim ready untuk handwriting aplikasi, tidak fabricate samples. Run queue untuk canvas fine tuning dan final validation tetap pending. Human collection/kurasi adalah prerequisite eksternal nyata, bukan pekerjaan yang dapat digantikan AI.

### 3. Menyamakan preprocessing dan input/output model
1. Di `ai/preprocess.py`, implementasikan canonicalization: orientasi/alpha composite; luminance grayscale; pilih polarity dari median pixel pada perimeter (median <127.5 → invert); Otsu dipakai untuk **foreground mask/crop**, bukan otomatis membinarisasi input network. Uniform image atau mask tanpa foreground menghasilkan status `empty`, tidak menjalankan classifier. Perimeter ambiguity/crop border contact dan occupancy masuk audit; curator menandai citra tidak layak bila objek sebenarnya clipped/background-dominated. Jangan memakai largest-component filtering yang membuang detached dots.
2. Bounding box mencakup **seluruh** foreground, koordinat inclusive (`max-min+1`); square side = ceil(1.4 × max(width,height)), centered on bbox, padding putih di luar gambar (jangan menggeser/clamp crop sehingga aspect/centering berubah). Resize ke 128×128 memakai bilinear dengan definisi half-pixel centers dan clamp sampling. Python dan browser memakai formula yang sama, bukan mengandalkan dua library resize yang berbeda. Retain grayscale black ink/white background, repeat ke tiga channels, normalisasi mean `[0.485,0.456,0.406]`, std `[0.229,0.224,0.225]`.
3. Definisikan `preprocessing_version="canvas-gray-v1"`, ukuran configurable hanya untuk ablation 128/224, dan serialization `preprocessing.json`. Network input NCHW float32, default training `[N,3,128,128]`; ONNX deployment fixed `[1,3,S,S]`, input name `image`, output `logits` shape `[1,C]`. Semua model satu script memakai C dan label hash identik. Output calibrated confidence adalah probabilitas kelas, **bukan** nilai akurasi tulisan/kemiripan geometris. Hybrid attention bukan detector/topology validator; jangan mengklaim posisi diakritik tervalidasi hanya karena top-1 benar.
4. Augment train-only setelah split: affine rotation ±5°, translation ±5%, scale 0.9–1.1, white fill, lalu canonical resize; contrast 0.8–1.2. Pastikan transformed ink tidak terpotong dengan menambah padding sebelum affine dan recrop seluruh mask. Tidak ada flip, random erased diacritics, large rotation, destructive random crop, atau synthetic/font samples di holdout. Review contact sheet 100 augmented training samples per script untuk memastikan label/diakritik tetap masuk akal.

### 4. Membandingkan baseline, pretrained, dan hybrid secara adil
Buat `ai/models.py` dengan `build_model(model_name, num_classes)`; enum CLI literal `cnn`, `mobile`, `efficient`, `hybrid`, `mobile-scratch`. Semua logits C tanpa softmax di training head.

| Kandidat | Arsitektur persis | Inisialisasi/peran |
|---|---|---|
| cnn | 3 blok Conv3×3-BN-ReLU-MaxPool2, channels 32/64/128; adaptive average pool; Dropout0.2; Linear128→C | From scratch, baseline kecil |
| mobile | `torchvision.models.mobilenet_v3_small`; replace last classifier Linear dengan C | `MobileNet_V3_Small_Weights.IMAGENET1K_V1` |
| efficient | `torchvision.models.efficientnet_b0`; replace last classifier Linear dengan C | `EfficientNet_B0_Weights.IMAGENET1K_V1` |
| hybrid | MobileNetV3-Small `.features`; global avg pooled feature branch + spatial attention branch; concatenate → Dropout0.2 → Linear→C | CNN pretrained; attention/head random |
| mobile-scratch | Arsitektur mobile identik, `weights=None` | Ablation manfaat transfer, bukan kandidat yang sengaja dilemahkan |

Hybrid detail: derive feature channels dari backbone, adaptive pool ke 4×4, Conv1×1 projection ke 128, flatten 16 tokens, learned positional embedding `[1,16,128]`, dua pre-LayerNorm attention/FFN blocks dengan 4 heads, FFN256, GELU, dropout0.1, residual, final LayerNorm, mean token pool. Implementasi attention explicit QKV/matmul/softmax standar agar export tidak bergantung fused attention. Concatenate dengan global CNN pooled vector. Ini satu contoh **kombinasi CNN + spatial attention**, bukan pretrained ViT penuh. Referensi official: [MobileNet](https://docs.pytorch.org/vision/main/models/generated/torchvision.models.mobilenet_v3_small.html), [EfficientNet](https://docs.pytorch.org/vision/main/models/generated/torchvision.models.efficientnet_b0.html). Pretraining keduanya ImageNet; default transform original crop224. Input128 adalah fine-tuning experiment, bukan default pretrained transform.

Di `ai/train.py` gunakan recipe berikut, disimpan penuh dalam config/run manifest:
1. Batch64, AdamW, weight_decay1e-4, gradient clip1, cosine LR per phase, mixed precision hanya jika CUDA tersedia; RNG Python/NumPy/torch di-seed, versions/determinism limitations dicatat. CUDA OOM: kurangi batch64→32→16 dengan gradient accumulation sehingga effective batch64; jika batch16 tetap gagal, stop candidate dengan failure detail, bukan mengubah resolusi/scope tanpa pencatatan.
2. Pretrained models: **transfer/head phase 5 epoch**, backbone dan BN statistics dibekukan, head/new attention LR1e-3. Simpan frozen-backbone best dan metrics. **Fine tuning 30 epoch maksimum**, backbone terbuka dengan LR1e-4, head LR3e-4, mulai dari best transfer checkpoint. CNN dan mobile-scratch: maksimum35 epoch, LR1e-3, train seluruh network. Early stop fine-tuning/scratch patience7 berdasarkan selection macro-F1, improvement threshold1e-4; frozen phase tetap5. Best checkpoint tie → loss lebih rendah, lalu epoch lebih awal.
3. Primary loss ordinary cross entropy tanpa label smoothing agar confidence study tidak tercampur. Hitung counts dari train partition saja. Bila largest/smallest class count >1.5, sebelum architecture screening jalankan mobile seed42 pilot ordinary CE versus weighted CE dengan `clip(sqrt(median_count/n_c),0.25,4)`, renormalize mean1, recipe identik. Pilih loss menurut selection macro-F1, lalu min recall, tie ordinary CE; gunakan loss terpilih pada semua architecture screening/reruns/finalists, reuse mobile pilot pemenang sebagai screening run. Tidak menggabungkan weighted sampler dan class-weighted loss. Bila rasio <=1.5, semua memakai ordinary CE tanpa balancing tambahan.
4. Screening seed42: kelima candidate per script. Urutan round-robin: mobile Sunda/Lontara/Bali, cnn ketiganya, efficient ketiganya, hybrid ketiganya, mobile-scratch ketiganya; only permitted/data-ready script dapat dieksekusi, sisanya tetap pending. Pilih dua **family** terbaik per script dari `cnn/mobile/efficient/hybrid/mobile-scratch`, rerun seed43 dan44 dengan split/config sama. Laporkan mean±std macro-F1 dan actual checkpoint terpilih, bukan hanya seed terbagus.
5. Pada family teratas, jalankan ablation resolusi224 seed42 dengan recipe yang sama; gunakan input224 hanya jika selection macro-F1 naik >=0.005 dan kemudian lolos latency/size gate. Jika tidak, tetap128. Angka 0.005 adalah absolute F1, bukan 0.5 relatif. Abaikan arsitektur tambahan yang tidak terdaftar; tidak melakukan pencarian tak berbatas.
6. Jika canvas train tersedia, fine tune setiap finalist best checkpoint maksimum15 epoch memakai concat source-train + canvas-train, LR backbone3e-5/head1e-4, patience5, primary selection pada canvas-selection. Jika canvas train belum tersedia, simpan stage ini pending; jangan train pada canvas-validation untuk menyamarkan domain gap.

### 5. Menguji ensemble dan mendistilnya ke model ringan
Buat `ai/ensemble.py` dan evaluasi di `ai/evaluate.py`:
1. Simpan logits selection semua candidate terbaik dengan sample IDs dan label hash. Ensemble hanya dalam script yang sama dan **resolusi128**; reject ID/order/hash/resolution mismatch. Pilih maksimum tiga family128 tertinggi, satu checkpoint per family. Kandidat224 tetap standalone comparator, tidak dicampur ke ensemble. Wajib evaluasi equal-weight soft vote semua pasangan dan trio tersedia, lalu weighted soft vote pada pasangan/trio tersebut memakai simplex grid langkah0.25, weights nonnegative dan sum1. Single model ikut comparator. Tidak stacking pada training predictions dan tidak hard vote.
2. Probabilitas ensemble `p=sum(w_i*softmax(z_i))`; seleksi weights di selection saja, tidak calibration/test. Rank macro-F1, lalu minimum class recall, lalu lebih sedikit member. Laporkan gain dibanding single terbaik, confusion/error disagreement, inference cost, dan validation support; gain tidak dijanjikan.
3. Wajib coba knowledge distillation ensemble terbaik (atau ensemble equal-weight terbaik bila single tetap unggul) ke `mobile` **128×128, seed42**: initialize dari best supervised mobile128 checkpoint script itu, teacher frozen/eval. Gunakan hanya train data dengan augmentation train yang sama untuk student dan teacher; gunakan concat canvas-train jika stage canvas fine tuning tersedia. T=4; teacher target `sum(w_i*softmax(z_i/T))`; loss `0.5*CE(student,label)+0.5*T*T*KL(teacher_T || softmax(student/T))`, batch-mean KL. Maksimum20 epoch, LR backbone3e-5/head1e-4, patience5. Teacher logits/probability tidak dibuat dari validation/test; cache hanya unaugmented train bila transform identik, default infer on-the-fly.
4. Distilled student adalah kandidat baru, bukan otomatis substitute ensemble. Bandingkan supervised mobile, best single, hybrid, ensemble, student di source-selection dan canvas-selection secara terpisah. Family reruns dan teacher experiment tetap tercatat meskipun kalah.
5. Calibration setelah architecture/weights checkpoint dipilih: fit satu positive scalar temperature dengan NLL pada calibration partition, tidak selection; export temperature-adjusted logits. Laporkan NLL, Brier dan 15-bin ECE serta reliability data. Threshold confidence terendah dengan empirical precision >=0.95 dan >=30 accepted calibration samples; bila tidak ada, metadata `accept_threshold=null` (UI tidak memberi otomatis status benar). Ini bukan jaminan OOD detection atau pedagogical correctness. Unknown glyphs/scribbles perlu dilaporkan sebagai diagnostics tersendiri, bukan diklaim aman berdasarkan threshold.

### 6. Menjalankan eksperimen batch melalui Kaggle MCP secara terkontrol
1. Buat notebook builder dalam `ai/runner.py` (`build-notebook`) yang menghasilkan `ai/notebooks/<run_id>.ipynb`. Notebook self-contained: embed modul/config/split/label metadata sebagai initial source cell dan jalankan CLI stage tunggal. Tidak bergantung pada local repo ada di VM. Input dataset paths ditemukan dari `/kaggle/input` berdasarkan audited relative leaves, bukan mount name yang ditebak. Verify inventory/manifest hashes sebelum training; mismatch → abort.
2. Preflight ulang quota dengan `xd://mcp__kaggle_get_accelerator_quota` payload `{"request":{}}`. Resolve notebook owner dari akun Kaggle yang terautentikasi pada client/browser; public profile bukan alat membuktikan current owner. Jika write operation auth gagal, gunakan `/mcp reauth kaggle`/alur `authorize` yang didukung client; jangan meminta token chat atau memasukkannya ke notebook. Browser interaction user menjadi blocker eksplisit bila flow tidak bisa diselesaikan otomatis.
3. Gunakan `xd://mcp__kaggle_save_notebook` setelah membaca live schema. Request `slugNullable=<owner>/<unique-run-slug>`, `newTitleNullable`, `textNullable` string JSON ipynb, `languageNullable="python"`, `kernelTypeNullable="notebook"`, `isPrivateNullable=true`, `enableGpuNullable=true`, `enableTpuNullable=false`, `enableInternetNullable=true` saat mengambil pretrained weights, `kernelExecutionTypeNullable="SaveAndRunAll"`, `sessionTimeoutSecondsNullable=3600`. `datasetDataSourcesSetter` berisi hanya dataset yang status training allowed, memakai exact owner/slug di Findings; untuk data sendiri gunakan private dataset ref hasil upload yang berizin. Record actual mounted version/hashes; jangan asumsi setter ref tanpa versi menjamin immutable version. Tidak memanggil create_notebook_session sesudah save: batch sudah dijalankan oleh save.
4. Pakai GPU gratis default Kaggle; jangan memilih premium `machineShapeNullable`. Runtime preflight mencatat actual GPU, torch/torchvision/CUDA versions, imports, seed dan notebook version. Reuse pasangan torch/torchvision preinstalled yang kompatibel, unduh weights resmi satu kali dan simpan cache checkpoint sebagai notebook output. Lock actual resolved dependency versions ke environment manifest/requirements; jangan upgrade CUDA/torch sembarang. Missing lightweight packages dipasang pada notebook awal; jika environment exporter torch<2.6 pakai legacy `dynamo=False` untuk opset17, selain itu `dynamo=True`. Export failure di hybrid diselesaikan dengan explicit attention graph, bukan menghapus branch.
5. Hanya **satu job GPU aktif**. Jalankan CPU audit/notebook building/report work selagi job berjalan. Queue dalam `ai/runs/queue.json`: run_id, script, stage, model, seed, dependencies, status, owner/slug/version, dataset/split/label/preprocessing hashes. Jangan meluncurkan ulang queued/running job. Run_id deterministik dari stage/config/input hashes; setiap attempt slug unik sehingga status tidak tercampur versi concurrent.
6. Checkpoints `last.pt` dan `best.pt` ditulis atomik setiap epoch, meliputi epoch/phase, optimizer/scheduler/scaler/RNG state, best metric/patience, architecture/config/input hashes. Output `/kaggle/working/runs/<run_id>/` juga menyimpan metrics.json, per-class CSV, confusion matrix, predictions dengan sample IDs, environment/provenance, timestamps dan stdout log. Notebook training berhenti **gracefully pada 55 menit**, menghasilkan status `partial` dan output tersimpan sebelum timeout satu jam. Resume memakai output previous unique notebook via `kernelDataSourcesSetter=[<previous-owner/slug>]`; verify seluruh hashes, lanjut optimizer/epoch bukan memulai diam-diam. Reject incompatible resume.
7. Catat version dari save response/info; `get_notebook_info`, `get_notebook_session_status`, `list_notebook_session_output` memakai `request:{userName,kernelSlug,versionLabel}` sesuai mounted schema (resolve version label yang benar dari response, jangan menebak format). Download dengan `request:{ownerSlug,kernelSlug,versionNumberNullable,filePathNullable}`; paginate list outputs melalui pageToken. Verifikasi downloaded run manifest/version/checksum. COMPLETE harus disertai metrics dan checkpoints expected, bukan dianggap sukses hanya status job. ERROR: ambil failure/log, perbaiki penyebab, resume valid artifact; maksimal satu retry penyebab transient, persistent error disimpan blocked.
8. Sebelum submission, hitung available GPU seconds = total-used-reserved, sisakan 20% untuk export/final validation/recovery. Mulai job hanya bila sisa nonreserve >=3600 detik atau estimated remaining job runtime (diukur dari epoch actual) dengan margin20%, mana lebih kecil, dan timeout disesuaikan agar tidak melebihi allowance. Bila kuota tidak cukup, simpan queue pending, jangan membeli GPU/TPU atau menghapus eksperimen dari scope. Snapshot refresh sesudah deadline berarti remaining work yang tertunda tidak boleh diklaim siap submission.

## Assumptions & contingencies
- User memilih classifier canvas saja dan kuota gratis saja. Tidak menjalankan paid compute; kuota API snapshot diverifikasi ulang setiap submission.
- User belum menentukan perangkat target siswa. Workstation browser menjadi baseline eksplisit; tidak menyamar sebagai hasil tablet murah. Jika perangkat target disediakan, ulang benchmark identik pada perangkat itu sebelum klaim latency universal.
- Permission, curated glyph mappings, dan kontribusi tulisan manusia belum tersedia. Jalankan pekerjaan kode/audit yang reachable; unresolved rights → tidak train/upload/release sumber terkait, fallback consented own handwriting dengan label coverage yang sama; unresolved glyph mapping → benchmark source_label boleh, target latihan publik diblokir. Missing holdout → hasil provisional dan queue pending, bukan data sintetis menggantikannya.
- Apabila repo berubah atau modul AI/frontend benar-benar sudah ditambahkan sebelum eksekusi, baca implementasi baru lebih dulu; reuse preprocessing/label contracts bila setara, migrasikan seluruh affected callers jika kontrak berbeda. Jangan melakukan branch checkout/reset atau menimpa pekerjaan user untuk mendapatkan tree kosong.
- "Hasil maksimal" berarti best measured candidate di experiment matrix dan deployment constraints ini; tidak ada arsitektur, pretrained weight, atau ensemble yang dijamin unggul sebelum hasil tersedia.
